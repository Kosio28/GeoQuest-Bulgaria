1. Таблица Users (Потребители)

Съхранява информация за регистрираните играчи.

Полеv

Тип

Описание

id

UUID

Уникален идентификатор – първичен ключ

username

VARCHAR

Потребителско име

email

VARCHAR

Имейл адрес

created_at

TIMESTAMP

Дата на регистрация

Първичен ключ: id

Връзки: Един потребител може да има много игрови сесии.

Забележка: Данните за удостоверяване ще се управляват чрез Supabase Auth, а таблицата Users ще съдържа допълнителната информация за профила.

2. Таблица Locations (Местоположения)

Съхранява информация за местата, които могат да се появят в играта.

Поле

Тип

Описание

id

BIGINT

Уникален идентификатор – първичен ключ

name

VARCHAR

Име на мястото

region

VARCHAR

Географска област

latitude

DECIMAL

Географска ширина

longitude

DECIMAL

Географска дължина

image_url

TEXT

Адрес на снимката

difficulty

INTEGER

Ниво на трудност

fact

TEXT

Кратък географски факт

Първичен ключ: id

Връзки: Едно местоположение може да участва в много игрови рундове.

3. Таблица Game_Sessions (Игрови сесии)

Съхранява информация за игрите на потребителите.

Поле

Тип

Описание

id

BIGINT

Уникален идентификатор – първичен ключ

user_id

UUID

Връзка с потребител

total_score

INTEGER

Общ брой точки

rounds_count

INTEGER

Брой изиграни рундове

created_at

TIMESTAMP

Дата на играта

Първичен ключ: id

Външен ключ: user_id препраща към Users.id.

Връзки: Един потребител може да има много игрови сесии.

4. Таблица Game_Rounds (Игрови рундове)

Допълнителна таблица, която ще съхранява подробностите за всеки рунд.

Поле

Тип

Описание

id

BIGINT

Уникален идентификатор – първичен ключ

session_id

BIGINT

Връзка с игрова сесия

location_id

BIGINT

Връзка с правилното местоположение

guessed_latitude

DECIMAL

Избрана географска ширина

guessed_longitude

DECIMAL

Избрана географска дължина

distance_km

DECIMAL

Изчислено разстояние

points

INTEGER

Спечелени точки

difficulty

INTEGER

Ниво на трудност

Първичен ключ: id

Външни ключове:

session_id препраща към Game_Sessions.id.

location_id препраща към Locations.id.

Обяснение на връзките:

Един потребител може да има много игрови сесии (1:N).

Една игрова сесия съдържа много рундове (1:N).

Едно местоположение може да бъде използвано в много различни рундове (1:N).

Тази структура ще позволи съхраняване на резултатите, проследяване на историята и изграждане на класация.
